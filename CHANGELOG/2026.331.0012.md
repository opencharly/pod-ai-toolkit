# 2026.331.0012 — fix(ai-toolkit): persist the XDG cache home so model downloads survive a re-create

## Summary

The `ai-toolkit` candy declared its state and workspace volumes but **no cache volume**, so the
HuggingFace and torch caches lived in the container's writable layer. A training run pulls the Z-Image
base, its text encoder and tokenizer/VAE through `huggingface_hub` (`HF_HOME` defaults to
`$XDG_CACHE_HOME/huggingface`) and torch's downloads through `TORCH_HOME` (`$XDG_CACHE_HOME/torch`), so
every re-created container re-downloaded those multi-GB weights.

A `cache` volume at `~/.cache` — the XDG cache home both resolvers derive from `HOME` — now persists
them, and a runtime check asserts the structure: the cache path is a MOUNT POINT and
`huggingface_hub` resolves under it. No `HF_HOME`/`TORCH_HOME` is pinned.

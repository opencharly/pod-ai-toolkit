### The four runtime fixes

1. **State-splice ownership** — the splice removes the image's own `config/output/datasets` so the
   volume can replace them, and the service runs as `user`; those were root-owned, so `rm` failed and
   the launch script exited 1 under `set -e` **before `exec`**. Both services died
   `FATAL — Exited too quickly` with no message of their own. One bug, four live failures.
2. **`mkdir -p` before that chown** — `output/` and `datasets/` are runtime-created.
3. **Z-Image handler import** — the handler lives in ai-toolkit's own `extensions_built_in` tree, so
   python must run from the checkout root.
4. **`git config --system --add safe.directory /opt/ai-toolkit`** (path-scoped, never `*`), so git can
   read the tree at runtime regardless of the reader's uid — one mechanism rather than `-c` flags in
   every consumer.

### The `layer-supervisord` pin, and why there is none

An earlier revision pinned it, and `charly box validate` failed with

```
candy layer-supervisord resolved to multiple git tags with differing content
within one scope (box=ai-toolkit)
```

Another candy in the box already requires `layer-supervisord` at a different version, and charly
refuses to choose. Every candidate reproduced it — the current tag `v2026.314.0710`, that same commit
as a sha, and the older `v2026.271.1817` — because the defect was the **disagreement**, not the value.
The pin is removed; the box composes supervisord transitively. With it gone,
`charly box validate` reports **329 candies, 44 boxes, 49 deploys, 6 distros, 7 builders;
0 warnings, 0 errors**, and a downstream `skills: … "cachyos-os-skills" is not a candy of this
project` error vanished with it — a cascade, not a separate defect.

## Change classification

**This changes the image's Python environment substantially and adds a lock file**, and it swaps the
supervisord priorities so the UI starts before the worker. That is the point: the merged candy had an
interpreter and no training stack. Consumers get a resolved cu130 environment where previously
`import torch` could not succeed, and a UI that is reachable before its worker. No port, volume or
env-var contract changes, and no other candy is affected — the whole change is inside this candy's own
pixi project and its own service priorities.

**Rollback:** revert this branch. The candy returns to its interpreter-only project, which still
builds — it simply cannot train, which is the state this PR exists to leave behind.

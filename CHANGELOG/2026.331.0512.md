# 2026.331.0512 — feat(box): the ai-toolkit-cdi image and its disposable bed

## Summary

Move the `ai-toolkit-cdi` box and its `check-cachyos-ai-toolkit-pod` bed out of `distro-cachyos` into
the repo that owns the service (`AGENTS.md` "Repo classes and naming": a bed lives with the thing it
tests; a `distro-*` repo holds the distro family, not one service's box).

**The box** composes the LOCAL `ai-toolkit` candy — the box proves this tree, not a pinned release of
itself, and the distro copy pinned `@github.com/opencharly/pod-ai-toolkit:v2026.327.0939` — plus
`pod-dbus`, on the CDI pod base. The CUDA substrate still arrives from that base
(`podcdi.pod-cdi` composes `layer-cdi` → `layer-cuda`), so the candy keeps its toolkit-free
declaration: this is a genuine class-1 image, and the box does not re-add a toolkit it does not need.

**The project header, line by line** (the distro copy inherited all of it from its parent project):

- `defaults.platform: [linux/amd64]`, `defaults.tag: auto`, `defaults.registry: ghcr.io/opencharly`,
  `defaults.build: [pac]` — the arch, the naming and the package format a build in this repo needs
  without a parent defaulting it.
- `defaults.builder.{aur,cargo,npm,pixi}: arch.arch-builder` — **needed, not cosmetic**: a builder map
  does not cross a namespace boundary, and both the pixi and npm stages of this image depend on it.
- `defaults.merge.auto: false`, `merge.max_mb: 128` — the inheritance-time merge policy the distro
  family used; kept so the box behaves identically here.
- `import: podcdi / cachyos / arch` — the CDI pod base and the CachyOS base as **namespaced imports at
  the project root** (a namespace mounted by a discovered document does not resolve a box's own
  `base:`).
- `discover: path: box, recursive: true` — **load-bearing**: without it `box/ai-toolkit-cdi/charly.yml`
  is never discovered.

**One documentation divergence is corrected here.** This repo's `AGENTS.md` said the repo
"deliberately ships **no image** — the image that composes this candy lives in `distro-cachyos` /
`distro-fedora`". Both halves were already stale: there is no Fedora AI Toolkit box anywhere in the
org, and after this change the image lives **here**. The paragraph now describes what the repo is.

It also adds the canonical `.gitignore` (copied from `distro-cachyos`); this repo had none.

### This round

The first review caught a real mistake of mine, and all four blocks were the same defect:

**The moved-bed slice ran past the end of `check-cachyos-ai-toolkit-pod` and carried two foreign beds
with it** — `check-cachyos-comfyui-pod` and `check-cachyos-unsloth-studio-pod`. That was: code the body
never described (A1/T3), beds placed in a repo whose own class rule forbids them (ARCH, and the
`AGENTS.md` divergence it created, R1), a duplicate of the bed `pod-comfyui` now owns (R2), and two
un-run beds in the gate (A2/R10). The slice boundary was wrong, and the body's singular "the bed" was
right about the intent and wrong about the diff — the reviewer read the diff, which is the correct
behaviour.

Fixed by deleting both (`2a11597`): `charly.yml` now adds ONE bed, `box validate` reports **1 deploy**
(the real one, not the 3 the swept-in beds produced), and the ARCH/R1/R2 findings have nothing left to
attach to. The tested artefact is byte-identical — the box and `check-cachyos-ai-toolkit-pod` are
untouched by that commit, so the pasted bed run still covers them.
